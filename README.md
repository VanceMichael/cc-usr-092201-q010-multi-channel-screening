# 多渠道电影展映编排

描述影片多渠道授权、母版、场地和实际放映资料，并提供一个可执行的编排校验器：确认排期的同时锁住实际版权次数与场馆资源，任何重排都不能突破授权。

## 资料范围

领域资料位于 `fixtures/domain.json`（v2），结构约定见 `contracts/domain.schema.json`，样例全部使用虚构标识。

记录类型：影片母版、字幕与分级提示、放映授权、场地设备、排片场次、映后嘉宾、座席名额、惠民座席、适配问题、放映回执。

流程状态：待适配 → 已排片 → 可开放 →（需调整）→ 放映中 → 已核销 / 已取消。

### 授权四维

每场授权条款（grant）同时声明：

- **渠道**：影院 / 线上 / 户外 / 校园（"仅线下两场"= 影院、校园共 2 场，线上永不匹配）
- **地域**：线下举办地域与线上观众地域，按 `region_coverage` 归属展开；境外不被任何条款覆盖
- **时段窗口**：场次起止必须完全落在窗口内
- **次数**：已锁定（活动场次）+ 已核销（回执）≤ `max_screenings`

### 14 条不变量

`fixtures/domain.json` 的 `invariants` 列出完整清单（INV-01 ~ INV-14），要点：

| 编号 | 约束 |
| --- | --- |
| INV-01~04 | 授权次数 / 渠道 / 地域 / 时段窗口 |
| INV-05 | 母版所需设备必须是场地能力子集（DCP 母版不能上户外屏），不兼容即生成技术组工单、不落锁 |
| INV-06/07 | 字幕语种齐备、分级提示已绑定才能开放 |
| INV-08/09 | 场地时段唯一、嘉宾不撞期（含 30 分钟转场缓冲） |
| INV-10 | 发布名额 = 可售 + 惠民免费 = 容量（线上为限流值） |
| INV-11 | 确认排期原子锁定授权次数与场馆时段，任一失败全部不生效 |
| INV-12/13 | 变更最小牵动；改期、换厅、换母版必须重过全部校验 |
| INV-14 | 已核销必有回执：实际母版可核对、观众不超容量、恰好消耗一次权利 |

## 变更的牵动范围

| 事件 | 只牵动 | 不牵动 |
| --- | --- | --- |
| 母版校验失败 | 该场适配问题、技术工单、发布状态 | 其他场次；未确认提案不锁任何资源 |
| 嘉宾改期 | 嘉宾↔场次关联 | 排期、授权、场地、名额 |
| 户外取消 | 该场状态、释放授权与场地、退全额票、解除嘉宾 | 其他渠道/影片场次 |
| 线上地域限制 | 超地域订单拦截 | 线下场次、授权次数 |
| 换厅 | 场地占用、设备适配、容量名额重算 | 授权次数、嘉宾 |
| 开场前退票 | 座席占用 | 权利计数（按实际播放核销） |

## 代码

- `domain_context/loader.py`：读取并检查资料完整性与记录间引用
- `domain_context/scheduling.py`：`Schedule` 校验器，方法包括
  `propose`（只校验+开工单）、`confirm`（原子锁定）、`publish`（名额一致才发布）、
  `sell` / `refund`、`detach_guest` / `attach_guest`、`report_issue` / `resolve_issue`、
  `cancel`、`change_hall`、`reschedule`、`close_out`（逐场核销）、`reconcile`（版权方对账）、
  `rights_usage`（剩余权利）、`audit`（全表不变量巡检）

所有写操作先在副本上校验，违规抛 `SchedulingError` 且状态不变。
